# anotacao/

Guidance for working in this directory (moved from the root `CLAUDE.md`; user docs are in `README.md`, plans in `PLANO-REVISAO.md` and the root `OBJETIVO.md`).

Assisted annotation: state lives in a SQLite database, `<saida>/anotacoes.sqlite` (phase 3b, schema and all access in `saida.py`: classes, lotes, imagens with voto/motivo, execucoes, propostas, revisoes, votacoes/votos/caixas_voto/caixas_voto_membros (T6/T7: consensus boxes in approved training images, one box per object (consensus or conflict) in failed ones; a class-less union in test images; each box records which proposal boxes it came from); schema v7 (`conjunto` and `capturada_em`, the UTC capture time, live in `imagens`; `auditoria` in `votos`/`imagens`), no migrations: a database of another version is refused and recreated by re-importing; every image belongs to a lote (`imagens.lote` NOT NULL), so images only enter through `importar.py`; proposals and reviews are never overwritten, the current one is the highest id; `labels/` (revised images, plus vote-approved ones still pending), `treino.txt`, `teste.txt`, `revisadas.txt` and `data.yaml` (train: treino.txt, val: teste.txt: the human-annotated test base is the training validation set, and with no revised test image the YOLO is not trained, on purpose) are generated from it, `anotar.py --exportar` regenerates them; every write is a `BEGIN IMMEDIATE` transaction; older output dirs with `imagens.csv` are refused; the Colab notebook works on a local copy and backs it up to Drive); `importar.py` copies a batch (lote, now just an import with a region of interest) into the shared `images/` store and registers each image with its own train/test set, drawn per image by name hash, ~1 in 10 to test (decision 7 revised 2026-11-15: capture (T4) must keep frames apart so per-image drawing doesn't leak scenes; revised again the same day: T4 captures on a timer spaced at least Δ (above the camera-crossing time), not by the detector, and stamps each frame with its capture time; importar.py `--janela` (Δ, default 4 s = the capture's `intervalo_s`, 10 s before 2026-11-24, also in pipeline.py) reads the capture time from the source file (EXIF `DateTimeOriginal` with subsec/offset, else a phone-style `20250503_140329` name; local time without offset), chains images closer than Δ (including already-imported ones) into a group that goes to one set (the already-imported members' set, else the draw of the earliest name), lists the groups and warns when a group already spans both sets, keeping the per-image draw otherwise; a belt-segment log was proposed and dropped to keep belt and annotation independent; object tracking (`model.track`) is only evidence in the capture log and drives servo triggering in T15; decision 19: the same physical object may appear in train and test, accepted as a limitation (vary objects during capture, read test metrics as optimistic, weight the external base more in T13)); `anotar.py` runs an annotator over imported pending images from its `ANOTADORES` registry (detectors subclass `Detector` and implement only `carregar()`/`pontuar()`; Grounding DINO and OWLv2, open-vocabulary, with the prompts (a string or a list per class) in `classes.yaml`; and `yolo`, the team's `best.pt`, matched to the classes by name. These three are the voting trio, decision 17) and writes proposals (every box from `--piso` 0.05 with its class; the read thresholds `confianca`/`confianca_classe` are stored in the run's parameters and applied by readers via `saida.separar()`) to the database, never to `labels/`; output `anotacoes/` is gitignored; `revisar.py` serves `revisar.html` plus a JSON API on 127.0.0.1; every review starts from the image's current vote (no vote, no review; `--aceitar` was removed): the default queue (`a_revisar`) holds failed votes and test images, the edit starts from the vote boxes, one per object (a failed training vote stores the union of the annotators' boxes: consensus when all found it with the same class, otherwise a class-less 'conflito' whose search offers the proposed classes as suggestions with keys 1-3; there are no numeric shortcuts for classes.yaml anymore), candidates come from all annotators, test images are reviewed without pre-annotation (T9): they open with no boxes and no class/confidence/annotator, the reviewer adds each object by click (candidates: one visible box per union group plus the below-threshold ones), and the server refuses `voto`-origin boxes on them; pending images can be edited (change class, remove, add a box by clicking a stored candidate, undo/redo, save, discard), each review box records its origin (voto/proposta/candidata) and each review is a new row in the database (drawing/moving boxes by hand is deferred, decision 12; reopening is phase 5); the page sends the `voto_id` it showed and gets 409 if the image was voted again; `visualizar.py` stays as the static `file://` page; `votar.py` (T6) applies the strict NooN vote (the pure functions live there; `avaliar.py --voto` imports them) to pending images of training batches with a current proposal from every annotator, and writes the class-less union for test images (stored for comparison, never shown), and records each vote with the proposals it used; approved images stay `pendente` with `voto = aprovada`, and a human review overrides them; T8 blind audit: ~5% of approved (`--auditoria`, name hash, stable on revote) get `votos.auditoria`/`imagens.auditoria`, stay approved and in treino.txt, but revisar.py's API shows them as `falhou` in `a_revisar` with no final labels, so the failure `motivo` is never sent to the page for any image; `pipeline.py` (T14) chains importar → anotar.py once per annotator of `anotadores.yaml` (name, type, anotar.py options; the trio by default) → votar, checking the whole config through `anotar.ler_argumentos` before importing or loading any model; it resumes because anotar.py skips images that already have the annotator's proposal and the vote skips already-voted ones, and the votacao records the config; `metricas.py` (T10, RF13) reads `saida.ler_registros()` and reports vote approval and failure reasons, the blind-audit error (fully-correct fraction with a Wilson 95% interval), correction outcomes and active review time per group (falhou/auditoria/aprovada/teste), and each annotator's precision/recall against the saved review, with and without class, split train (biased: review starts from the vote) and test, plus data-consistency warnings; `--json`; the review page has a Métricas tab over `GET /api/metricas`, blind by default (`medir(cega=True)`: audited images count as falhou, no audit block, vote block only as the queue shows it) with an opt-in toggle that reveals the audit; `avaliar.py` scores saved proposals (no model run; validation images are imported and annotated like any batch, matched to the team labels in `legado/database` by original name) for coverage per read threshold, class per confidence band, detection and click-to-box, plus `--comparar` (joint class error of two annotators) and `--voto` (strict NooN vote per image, and consensus per box), after applying `correcoes_rotulos.yaml` (the team labelled all glass as `Glass bottle`; corrections are by .txt line, legado/ stays untouched); `anotar_colab.ipynb` runs it on Colab; `PLANO-REVISAO.md` plans T1, the generic annotation framework and the review/edit page.
